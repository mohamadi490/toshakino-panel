# سؤال‌ها و پاسخ‌های بک‌اند

مرجع پاسخ‌ها: `docs/contracts/backend-answers.md` (از روی کد واقعی ریپو `toshakino-api`). **قرارداد (OpenAPI + کد) مرجع است**؛ اگر چیزی نقض شد این فایل اصلاح می‌شود.
برچسب‌ها: ✅ پاسخ داده شد و در پنل اعمال شده · 🔧 بک‌اند باید بسازد (بک‌لاگ) و پنل تا آن زمان رفتار موقت دارد · 📌 تصمیم استقرار/محصول.

## پاسخ‌داده‌شده و اعمال‌شده
| # | موضوع | پاسخ بک‌اند | رفتار پنل |
|---|---|---|---|
| Q1 | مجوزها | ۲۰ کد ثبت‌شده؛ نام‌ها یکدست `<منبع>.<عملیات>` نیستند (مثلاً `orders.update`، `categories.write` برای برند و دسته، `media.write` برای فهرست/آپلود/حذف) | رجیستری `core/authorization/permissions.ts` با همین کدها؛ جدول endpoint ← مجوز در `docs/modules/core.md` |
| Q3 | انتقال وضعیت سفارش | `pending_payment→cancelled`، `paid→shipped/cancelled`، `shipped→delivered`؛ ادمین `paid` نمی‌زند؛ لغو موجودی را برمی‌گرداند؛ غیرمجاز `409 invalid_status_transition` | جدول در UI (B5) + تصمیم نهایی با سرور |
| Q5 | مشتری‌ها | مشتری = کاربر با `role.isStaff=false` (نقش سیستمی `customer`) | ماژول جدا نداریم؛ فیلتر `roleId` در کاربران |
| Q7 | ویرایش هویت کاربر | عمداً ممکن نیست (ورود/OTP به آن‌ها وابسته است) | فقط `fullName/roleId/isActive/newPassword` |
| Q8 | کدهای خطا | `message`/`detail` انگلیسی؛ کد فیلد استاندارد Pydantic یا کد دامنه؛ فهرست در پیوست ب | نگاشت فارسی همه ۷۹ کد (تست می‌کند هیچ‌کدام جا نیفتد) + پیام عمومی برای کد ناشناخته |
| Q9 | رسانه | ۵MB؛ فقط JPEG/PNG/GIF/WebP با magic bytes (SVG نه)؛ `media_too_large` (413)، `media_empty`، `media_unsupported_type`؛ **حذف فایلِ در‌حال‌استفاده مجاز است** (`media_in_use` وجود ندارد)؛ `alt` روی رسانه ذخیره نمی‌شود | B3: هشدار قبل از حذف («لینک‌های شکسته ممکن است ایجاد شود»)؛ `alt` در فرم محصول/دسته/برند |
| Q10 | تصاویر محصول | حداکثر ۲۰؛ ترتیب آرایه = ترتیب نمایش؛ اولی شاخص؛ `alt` اختیاری (≤۲۰۰)؛ در PATCH کل آرایه جایگزین می‌شود | B4 |
| Q11 | صفحات | `body` HTML با sanitizer allow-list سمت سرور در زمان ذخیره؛ `PUT` (نه PATCH)؛ `page_slug_taken` | C3: `textarea` + پیش‌نمایش (ممکن است کمی با نسخه ذخیره‌شده فرق کند) |
| Q12 | معنی `null` | `exclude_unset`: ارسال‌نشده = تغییر نده؛ `null` = پاک کن؛ فیلد الزامی با `null` → ۴۲۲؛ همین قاعده برای PUTهای صفحات/تنظیمات | **همان رفتار فعلی ما درست است** (فقط فیلدهای تغییرکرده، `null` صریح برای پاک‌کردن) |
| Q13 | slug | خالی/`null` ← از نام ساخته می‌شود (یونیکد/فارسی حفظ)؛ صرفاً عددی نمی‌شود؛ تکراریِ خودکار پسوند `-2`، تکراریِ صریح `409 slug_taken`؛ تغییر slug ریدایرکت ثبت می‌کند؛ یکتایی فقط بین موارد زنده | slug اختیاری؛ تغییر آن هشدار «URL عمومی عوض می‌شود» |
| Q14 | `specs` | آبجکت آزاد `{کلید: مقدار}`؛ ترتیب تضمین‌شده نیست | ردیف‌های کلید/مقدار متنی |
| Q15 | ارسال | اولویت شهر ← استان ← سراسری؛ `PUT` همان محدوده را جایگزین می‌کند؛ `weightTiers` اکیداً صعودی با **آخرین (و فقط آخرین)** پله `upToGrams:null`؛ `fixed` فقط `cost`، `weight` فقط `weightTiers`؛ روش فعال بدون قاعده برای شهر مشتری نمایش داده نمی‌شود | C1 با همین اعتبارسنجی + هشدار «روش فعال بدون هیچ قاعده» |
| Q16 | داشبورد | `revenue` = مجموع سفارش‌های paid/shipped/delivered؛ `days` ۱ تا ۳۶۵؛ روزها بر اساس `BUSINESS_TIMEZONE` (Asia/Tehran)؛ روزهای بدون فروش صفر | تاریخ سری به‌صورت date-only و بدون تبدیل منطقه زمانی؛ بدون مقایسه با دوره قبل |
| Q17 | نقش‌ها | فهرست کامل و بدون صفحه‌بندی با `permissions`؛ نقش‌های سیستمی `super_admin` و `customer`: نام/حذف → `role_protected` | فرم از فهرست؛ نام نقش سیستمی قفل |
| Q18 | PII سفارش | مجوز جدا ندارد؛ هر کس `orders.read` دارد همه فیلدهای `shipping` را می‌بیند | بدون ماسک |

## 📌 تصمیم‌های استقرار
- **Q2 - کوکی refresh**: `admin_refresh_token`، مسیر `…/admin/auth`، `SameSite=lax` (قابل تنظیم)، rotation + تشخیص استفاده مجدد. بررسی Origin/هدر سفارشی **نداریم**. در production پنل و API باید **same-site** باشند (مثلاً `admin.tashkino.ir` و `api.tashkino.ir`)، وگرنه `lax` کوکی را در fetch نمی‌فرستد (راه دیگر `SameSite=None; Secure`). در توسعه `localhost` با پورت‌های متفاوت same-site است.
