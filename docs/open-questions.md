# سؤال‌های باز برای تیم بک‌اند

هر مورد با «اگر پاسخ نیامد» رفتار موقت پنل مشخص شده است. وقتی پاسخ آمد، همین فایل و `docs/contract-analysis.md` به‌روز می‌شود.

| # | سؤال | اثر | تا پاسخ، پنل چه می‌کند |
|---|---|---|---|
| Q1 | **فهرست کد مجوزها** و اینکه هر endpoint ادمین کدام مجوز را می‌خواهد (OpenAPI نمی‌گوید؛ فقط `system.read` در راهنما آمده). لطفاً خروجی `GET /admin/permissions` و جدول «endpoint ← مجوز» را بدهید | منو، روت‌ها و دکمه‌ها بر اساس `permissions` کاربر مخفی/نمایش داده می‌شوند | رجیستری `core/authorization/permissions.ts` با نام‌های **حدسی** `<منبع>.<عملیات>`؛ در صورت اختلاف، بخش‌ها از منو پنهان می‌شوند (سرور همچنان مرجع است). در صفحه نقش‌ها کد واقعی از API خوانده می‌شود |
| Q2 | محافظت **CSRF** برای cookie ی refresh چیست (SameSite، بررسی Origin)؟ هدر `X-Requested-With` در CORS مجاز نیست | امنیت refresh | هیچ هدر سفارشی ارسال نمی‌شود؛ فقط `withCredentials` |
| Q3 | **انتقال‌های مجاز وضعیت سفارش** (`pending_payment → paid → shipped → delivered`، لغو از کدام‌ها؟) یا فیلد `allowedTransitions` در `OrderRead` | UI نباید ماشین وضعیت را حدس بزند | همه وضعیت‌ها به‌جز وضعیت فعلی پیشنهاد می‌شود؛ سرور با `409 invalid_status_transition` رد می‌کند و پیام فارسی نشان داده می‌شود |
| Q4 | سفارش‌ها: لطفاً `GET /admin/orders/{id}`، جستجو (`q`: شماره سفارش/موبایل)، بازه تاریخ، مرتب‌سازی و **نام/موبایل مشتری** (با مجوز) اضافه کنید. الان فقط `userId` و فیلتر `status` هست. پرداخت‌ها (`PaymentRead`) هم در API ادمین نیست | کارایی عملیات روزانه | جزئیات سفارش داخل همان فهرست (پنل کشویی) نمایش داده می‌شود؛ مشتری با `userId` و لینک به کاربر |
| Q5 | **مشتری‌ها**: `/admin/customers` ندارید. آیا «مشتری = کاربر با نقش غیرکارمند» است؟ فیلتر `isStaff` روی `/admin/users` ممکن است؟ | ماژول مشتری | ماژول جدا ساخته نمی‌شود؛ در «کاربران» با فیلتر نقش و نشان کارمند/مشتری دیده می‌شود |
| Q6 | **موجودی**: endpoint فهرست Variantها با موجودی (مثلاً `GET /admin/inventory?lowStock=&q=`)، تعدیل نسبی (`delta`) با دلیل و تاریخچه، و کنترل هم‌زمانی (`version`/`If-Match`). `PATCH variant {stock}` مقدار مطلق است و می‌تواند تعدیل هم‌زمان ادمین دیگر را بازنویسی کند | درستی موجودی | فهرست از `/admin/products` (Variantها) ساخته می‌شود؛ تنظیم مقدار مطلق با هشدار؛ بدون تاریخچه |
| Q7 | در `UserUpdate` فقط `fullName/roleId/isActive/newPassword` هست؛ **تغییر ایمیل/موبایل/نام کاربری** عمداً ممکن نیست؟ | فرم کاربر | فقط همین فیلدها ویرایش می‌شود |
| Q8 | **فهرست `code` خطاهای سطح فیلد** (`fieldErrors[].code`) و زبان `message` | پیام فارسی دقیق | `code`های شناخته‌شده نگاشت می‌شوند؛ بقیه «مقدار واردشده معتبر نیست» + `field` |
| Q9 | رسانه: سقف حجم/نوع فایل، آیا حذف فایلِ در‌حال‌استفاده رد می‌شود (`media_in_use`؟)، امکان ویرایش `alt` بعد از آپلود؟ | کتابخانه رسانه | پیش از آپلود: بررسی حجم (۵MB) و نوع تصویر در UI صرفاً راهنما؛ سرور مرجع است |
| Q10 | تصاویر محصول: ترتیب آرایه = ترتیب نمایش؟ تصویر اول شاخص است؟ `alt` اجباری؟ | فرم محصول | ترتیب آرایه، اولی شاخص؛ `alt` توصیه می‌شود |
| Q11 | صفحات: `body` چه HTML ای را می‌پذیرد (sanitizer)؟ ویرایشگر WYSIWYG مورد انتظار است؟ | ماژول صفحات | `textarea` با پیش‌نمایش پاک‌سازی‌شده سمت کلاینت؛ ذخیره همان متن |
| Q12 | `PATCH`/`PUT`: در بدنه‌هایی که همه فیلدها `nullable` هستند، **`null` یعنی «پاک کن» یا «تغییر نده»**؟ (`exclude_unset`؟) | همه فرم‌های ویرایش | فقط فیلدهای تغییرکرده فرستاده می‌شوند؛ برای پاک‌کردن `null` صریح |
| Q13 | `slug` خالی/`null` ← خودکار از نام ساخته می‌شود؟ قاعده فارسی؟ با تغییر slug ریدایرکت خودکار ثبت می‌شود؟ | دسته/محصول/برند | slug اختیاری می‌ماند؛ تغییر آن هشدار می‌دهد |
| Q14 | `specs` (آبجکت) ساختار انتظاری دارد؟ کلید/مقدار متنی ساده؟ | فرم محصول | ردیف‌های کلید/مقدار متنی |
| Q15 | ارسال: اولویت قواعد (شهر ← استان ← سراسری)، معنی `weightTiers` (`upToGrams: null` = آخرین پله؟)، اجباربودن حداقل یک قاعده برای روش فعال | ماژول ارسال (فاز ۲) | مستندسازی و تست؛ پیاده‌سازی بعد از پاسخ |
| Q16 | داشبورد: تعریف `revenue` (طبق توضیح OpenAPI: سفارش‌های paid/shipped/delivered)، آیا مقایسه با دوره قبل ممکن است؟ | داشبورد | همان تعریف را نمایش می‌دهیم؛ بدون مقایسه |
| Q17 | نقش‌ها: `GET /admin/roles/{id}` ندارد؛ فهرست کامل است (بدون صفحه‌بندی)؟ آیا `permissions` هر نقش در فهرست می‌آید (طبق schema بله)؟ | فرم نقش | فرم از فهرست می‌خواند |
| Q18 | آدرس/موبایل گیرنده در `shipping` سفارش: آیا به مجوز خاص (PII) وابسته است؟ | حریم خصوصی | با مجوز `orders.*` که کاربر دارد نمایش داده می‌شود |
